Motivation

Why Build a Hypervisor from Scratch?

No Host OS Beneath It Runs directly on the hardware after UEFI firmware hands over control of the machine.
Direct Linux Boot Acts as its own bootloader to drop a Linux kernel straight into 64-bit execution without GRUB.
Multi-Architecture Goal Structured from day one to compare how x86_64, ARM64, and RISC-V approach hardware virtualization.

Virtualization is the foundation of modern cloud computing and container isolation, yet for most engineers it remains a black box hidden behind mature tools like KVM, Hyper-V, or Xen. Duriel is a hands-on research project built on my core engineering philosophy: the best way to truly understand a layer of the stack is to build it yourself with zero external dependencies.

Unlike Type-2 hypervisors (which run as normal applications inside Windows, macOS, or Linux), Duriel is a Type-1 (bare-metal) hypervisor. When the computer powers on, motherboard firmware (UEFI) loads Duriel directly. There is no operating system, no C standard library, and no existing memory manager, so every abstraction has to be built from raw physical memory and CPU registers up.

Rather than relying on an external bootloader inside the virtual machine, Duriel also implements the Linux boot protocol directly: it unpacks a Linux kernel image and initial ramdisk into guest memory and boots the guest straight into a working Linux userland.

Technical Decisions

Why This Stack?

Bare-metal development traditionally requires a fragile web of C, assembly, and architecture-specific cross-compilers. Duriel uses a modern toolchain to keep the codebase clean and reproducible:

Zig Instead of C

Hardware specifications are full of bit-packed control structures where a single off-by-one bit shift causes a silent triple fault. Zig's bit-level packed struct types and compile-time (comptime) size checks let the compiler verify hardware data structures before the code ever runs.

Zero-Friction Cross-Compilation

Building firmware for x86_64, ARM64, and RISC-V in C usually means installing three separate compiler toolchains. Zig's built-in build system compiles all three architectures from a single command out of the box.

Nix for Reproducible Guests

To test a hypervisor, you need a known-good guest operating system. Duriel uses a Nix flake to declaratively build a minimal Linux kernel and BusyBox ramdisk so the test environment is identical on every machine.

QEMU & Hardware KVM Testing

Paired with automated Make targets that package the EFI System Partition and launch Duriel inside QEMU across x86_64 (with nested KVM hardware acceleration), AArch64, and RISC-V virtual machines.

Engineering Challenges

What Makes It Interesting?

Surviving the UEFI Handoff Transitioning from firmware boot services to owning the raw machine without losing the memory map or crashing the CPU mid-flight.
Two-Dimensional Memory Isolation Managing both the hypervisor's own page tables and hardware Nested Page Tables (NPT) so the guest OS thinks it owns physical RAM while remaining completely isolated.
Bootloader-Free Linux Launch Skip-loading BIOS/UEFI inside the guest by constructing the Linux setup header and memory map directly in guest RAM and jumping straight to 64-bit kernel code.
Debugging Without an OS Wiring Zig's standard logger and panic handler directly to hardware serial ports so crashes print human-readable fault and register state instead of silently rebooting.
